我在岩土所读博，导师接了一条城际铁路的勘察项目，组里每周都有一批三轴试验结果出来：同一土层取若干试样，各在不同围压下剪到破坏，记下破坏时的大小主应力，固结不排水试验还会记孔压。之后要按土层整理强度参数 c、φ 交给设计院。现在的做法是在 Excel 里手画莫尔圆、目测切线，同一层土不同人做出来的 c 能差一倍；试样补做或者某个试样被判无效以后，也没人说得清交出去的参数用的是哪几个试样。想请你做一个后端。
数据按项目—钻孔—土层—试样组—试样的层级组织，每一级都能增删改。强度标定的核心：每个有效试样在破坏时对应一个莫尔圆，求一条摩尔–库仑包络线使它尽量与这些圆相切，给出 c、φ 和每个试样到包络线的偏离量。总应力和有效应力两套参数都要能算，有效应力用孔压扣减。是在 p–q 空间做线性回归再换算，还是直接以包络线到各圆的距离为目标求解，或者别的方法，由你选，并在文档里说明它对 c 的影响以及只有两个试样时的表现。往返检验必须成立：用给定的 c、φ 正向生成各围压下的破坏应力，再拿去标定，要还原原参数。例如 c = 10 kPa、φ = 30°，围压 100、200、300 kPa 时破坏大主应力约为 334.64、634.64、934.64 kPa，标定后应得到 c = 10 kPa、φ = 30°。两个试样时包络线唯一确定，只有一个时不能标定。
土层的设计参数由该层全部有效试样组按统计方法给出标准值：均值、变异系数，以及按规范思路折减后的值，折减方式写清依据。试样被修改、作废或新增时，所在试样组和土层的标定结果都要更新，之前每一版都保留，能查到任一历史时刻某土层交出去的参数，以及当时用了哪些试样。两个人同时编辑同一个试样组，基于旧版本的提交必须被拒。还要能按项目列出自上次导出以来哪些土层的参数变了、变了多少。
这些输入要拒绝：大主应力不大于小主应力；围压为负；孔压不小于围压；同一组里围压重复；拟合得到的 φ 不在 0°–60° 之间或 c 为负——这种情况要明确报出来，不能截断了事。
技术上用 Go 1.22 + Gin，存储选 PostgreSQL 16；二进制在 golang:1.22-alpine 里分阶段编译，库跑在 postgres:16-alpine 里，整体写成一份 compose 清单。包的划分由你决定，保持职责清晰。go test 要覆盖：往返还原，两点精确与单点拒绝，总应力与有效应力两套结果，统计取值，修改后结果更新而历史版本不变，并发冲突，以及各类非法输入。
